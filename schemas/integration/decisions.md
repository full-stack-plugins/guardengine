# Integration contract decisions — implementation baseline

Scope: approved `add-versioned-guard-integration-contracts`, tasks 1.1–1.6. These are reversible implementation decisions pending independent review; no production approval/identity provider is selected. Existing engine v1alpha1 is unchanged.

- Version `guard.integration/v1alpha1`, kind `GuardRunEnvelope`; fields exactly follow docs/integration-contract.md. Capability is an explicit API parameter, not an added wire property: `EvidenceProfile::EngineBacked` or `NativeOnly`. Consumers must state which they require. Native-only never satisfies EngineBacked.
- Rust module `guardengine::integration`; `GuardRunEnvelope`, `RunBinding`, `Producer`, `Coverage`, `CoverageStatus`, `Artifacts`, `ArtifactRef`, `Diagnostic`, `RunStatus`, `EvidenceProfile`, `IntegrationError`. Struct fields snake_case in Rust, camelCase on the wire. All objects deny unknown fields; nullable keys are required in the JSON contract even when null.
- Public loading: `load_envelope_json(bytes: &[u8], profile: EvidenceProfile) -> Result<GuardRunEnvelope, IntegrationError>`; `GuardRunEnvelope::validate(profile)`. Loading is bounded and rejects duplicate JSON keys; no CLI changes. Missing binding uses `TransportDiagnostic` separately, never fake OIDs/envelopes.
- repoId/taskId/worktreeId and producer fields are nonblank bounded strings. requirementIds and coverage scope arrays are sorted, unique, nonblank. At least one requirement and required scope is required. observed scopes can include additional scopes; missingScopes must equal required minus observed. Complete iff missingScopes is empty; partial iff nonempty. Actual analyzer-scope completeness also checked against report when engine-backed artifacts are verified.
- candidateOid/baseOid: lowercase full SHA-1 (40 hex) or SHA-256 (64 hex); shape is validated here, actual repository object/type/existence remains a Git/domain/controller responsibility. Other algorithms require an explicit version/capability update. mergeGroupId nullable outside queue; baselineDigest nullable only with external policy declaring no baseline. Engine schema cannot authenticate that policy.
- Digests are lowercase `sha256:` plus 64 hex. Artifact URIs are opaque `artifact://<store>/<key>` identifiers, no empty segments, dot traversal, percent/backslash/query/fragment or credentials. The engine never resolves URLs/files/network. Caller provides exact bounded bytes; verify hashes those exact bytes, not a normalized replacement.
- UTC RFC3339 timestamps parsed using time 0.3.44 (declared MSRV 1.81, below project 1.85). Require zero offset, finishedAt >= startedAt and expiresAt is a required nullable key; non-null value >= finishedAt. Preserve serialized timestamp spelling; eligibility compares parsed instants. No wall clock in core evaluation.
- Bounds: envelope JSON at most 1,048,576 bytes; each string at most 4096 UTF-8 bytes; each collection at most 4096 entries; referenced artifact supplied to verifier at most 16,777,216 bytes. JSON nesting maximum 32. Schema covers structural/character constraints, Rust loader additionally enforces byte/depth and cross-field invariants. Limits are conservative initial safety limits, not measured capacity claims.
- Canonicalization for envelope content identity is compact serialization of the validated typed struct in pinned field order, without sorting additional data or altering current engine evidence canonicalization. Producers supply sorted set arrays; diagnostics and artifact domain order are preserved. Golden bytes/digests pin this representation. Cross-language canonical JSON standard is not asserted.
- completed requires a non-null Decision; error/cancelled requires null and at least one diagnostic; failure report ref is null, partial diagnostic artifacts may be retained under domain. Completed EngineBacked requires contract/facts/report. NativeOnly requires report/facts/contract null and domain evidence; complete native scope is caller-proven and never inferred from exit 0 or zero findings. Native partial must BLOCK. Approval references never rewrite a report.
- `verify_engine_artifacts(envelope, contract_yaml, facts_json, report_json)` verifies exact referenced bytes, uses existing loaders and full recomputation, checks analyzer, snapshot, completeness and decision agreement. It does not prove producer authentication, Git OIDs or approval.
- New opt-in transport errors use `TransportDiagnostic { code, message }`; they have no decision or binding. No new command/flag is added to the existing binary in this phase. A later explicit integration CLI may expose this loader without changing evaluate/verify behavior.
- GE-TRUST ports will accept provider-verified records via a caller-implemented authentication trait, never a public deserialized trusted=true flag. No issuer, key, storage service or policy backend selected. Production identity, signing, publication and real-host activation need separate authority and evidence.

Review references and accepted task statuses are maintained in docs/implementation-progress.md; this record alone is not task completion.
