# Local integration artifact publication

`stage_attempt(private_root, &envelope, profile)` validates the envelope and writes bounded canonical bytes to a private temporary file in the selected store. `StagedAttempt::publish()` exposes a complete immutable per-attempt JSON file and never replaces an existing path. The final filename hashes the run ID; IDs are never interpreted as filesystem paths. A repeated run ID is a conflict, not permission to overwrite evidence. Cancellation by dropping the staged value leaves no final attempt.

This is an opt-in library surface. Historical `guardengine evaluate/verify --report` behavior is unchanged. Domain CLIs/controllers must explicitly adopt the new surface and handle its errors. Merely finding a JSON file does not make it current: compare expected binding/run ID/digest and use the separately protected generation/CAS and eligibility checks.

The first supported profile is private local Unix storage, verified on this Linux host. The root must already exist, must not be a symlink, and must have no group/other permission bits. The caller must protect the root and its parent hierarchy against untrusted writers for the whole operation. A world-writable store is rejected. This is not an OS sandbox against a hostile same-UID process; storage/service/tenant authentication and quotas remain controller responsibilities. Other platforms are unqualified; non-Unix publication rejects explicitly.

The implementation uses tempfile's no-clobber persistence in the same directory. On the tested Linux filesystem the final name appears only after complete bytes are flushed. Portability does not promise atomic temporary-name cleanup: a crash or filesystem error may leave an orphan temporary hard link. File bytes are synchronized before publication and the directory afterward. A directory-sync error after the final name is linked reports uncertain durability; inspect the expected final bytes/digest before retrying, never delete an existing record to force success. Fault recovery is not a global transaction across files and a database.

Root device/inode identity is captured. A changed store directory prevents commit; dropping a stage after directory replacement preserves an orphan in the old store instead of unlinking an unrelated entry in the replacement store. This check does not replace the protected-directory precondition or eliminate hostile concurrent same-user races.

Tests cover dropped staging, duplicate publication, unsafe roots, invalid envelopes before file creation, path-like run IDs, exact roundtrip bytes, and directory replacement during cancellation. `tests/adapter_compatibility.rs` separately exercises the real unchanged engine CLI for ALLOW/BLOCK/REQUIRE_APPROVAL/partial/error, stdout versus file output, consistent BLOCK verification and exact neutral-rule parity through the integration verifier.
