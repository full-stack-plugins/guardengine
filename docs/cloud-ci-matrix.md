# Prepared cloud-only platform qualification

The manual workflow `.github/workflows/guard-cloud-compatibility.yml` defines 21 combinations: seven repositories on Ubuntu24.04, macOS14 and Windows2022 hosted runners. It requires all seven full commit SHAs, uses a pinned checkout action with persisted credentials disabled, read-only contents permission, fixed Rust1.99.0, at most two simultaneous jobs and a40-minute job limit. No failure is converted into success, no branch-protection rule is changed, and no deployment/publish operation is present.

This workflow has only been prepared locally. It has **not** been pushed, dispatched or run on those hosted platforms. The selected source commits must become remotely available through a separately authorized review/push process before dispatch. Current cloud Linux execution evidence does not qualify macOS/Windows or a particular hosted CI image. Unsupported platform code may fail these jobs; that result remains a failure until fixed and reviewed.

`python scripts/cloud_guard_matrix.py --repository codeguard --root /path/to/seven/checkouts` prints the exact argv without executing. Add `--run` to execute. Each other Guard runs its full crate suite; CodeGuard runs the explicitly named `guard_integration_*` test targets discovered at the pinned commit. This limited CodeGuard profile does not qualify its complete native language/tool matrix or settle PR31's remaining platform tasks. Missing targets fail; ignored syscall tests remain ignored unless their separately documented environment is installed and explicitly exercised.

Source/tool identity is printed before the selected test command. All real platform evidence, including failures and unsupported slices, must be recorded before any support matrix is promoted. Native external tools not installed by the hosted image may fail; the workflow does not install an arbitrary provider, skip failed tests or quietly alter locked dependencies to obtain green.

Design references: GitHub's [workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax), including manual inputs, permissions and strategy limits; [pinned checkout4.2.2 source](https://github.com/actions/checkout/commit/11bd71901bbe5b1630ceea73d27597364c9af683). Hosted protection acceptance (GE3.6 and related specialist CI tasks) still requires the separately chosen authorized test repository/controller and real protection checks. Public release channels are independent of these local implementation and matrix-preparation steps.
